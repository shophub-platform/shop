# shop

This repository implements the application for a single shop on the ShopHub platform. Every shop a user creates through ShopHub is one instance of this application, deployed into Kubernetes by `shop-operator` through the `Shop` custom resource. The shop owner (admin) manages items and orders, while end customers browse items, add them to a cart, and pay with cryptocurrency through a Web3 wallet such as MetaMask, without using a traditional payment system.

## Role in the architecture

One instance of this application equals one shop. Each instance gets its own database (PostgreSQL or Redis, depending on the choice made when the shop was created in ShopHub), its own wallet, and its own configuration through Kubernetes ConfigMap and Secret objects generated by `shop-operator`. Payments are tracked on chain: a background service called `listener` watches Transfer events on Ethereum's Sepolia testnet and automatically updates an order's status once payment arrives at the shop's wallet.

## Repository structure

`shop-backend/` is the Go REST API service. Its `cmd/server/main.go` runs the HTTP server, including routes, middleware, and health checks, while `cmd/listener/main.go` is the background process that watches blockchain transactions and confirms payments. `internal/handler/` contains HTTP handlers for auth, items, cart, orders, config, and health. `internal/service/` holds the business logic, including auth, cart, order, and item services, plus `listener.go`, the blockchain event listener. `internal/repository/` is the repository layer with two implementations per entity, one for `postgres/` and one for `redis/` (the database choice is configurable per shop), plus mocks for tests. `internal/model/` defines the domain models for item, cart, order (with statuses PENDING_PAYMENT, PAID, PROCESSING, SHIPPED, DELIVERED, and CANCELLED, along with the valid transitions between them), and user. `internal/middleware/` covers JWT auth, logging, metrics, and an internal API key. `internal/metrics/` and `internal/tracing/` provide Prometheus metrics and OpenTelemetry tracing. `api/openapi.yaml` is the API specification.

`shop-frontend/` is the Angular front end application. `core/services/web3.service.ts` integrates with MetaMask through ethers.js, handling wallet connection, switching to the Sepolia testnet, and sending mUSDT transfers. `features/admin/` covers item management and order review for the admin. `features/items`, `features/cart`, and `features/checkout` handle browsing and searching items, the cart, and checkout with cryptocurrency payment. `core/guards/admin.guard.ts` and `auth.guard.ts` protect routes by role.

## Main features

Item management for the admin covers creating, editing, and deleting items, including name, price, and stock quantity. Order review for the admin lists orders along with their statuses and transitions. Item browsing and search for customers supports filtering by price and stock availability, text search, and pagination. The cart and checkout flow lets customers add items to a cart and pay in cryptocurrency, using a mock USDT ERC20 token (mUSDT) through a MetaMask wallet on the Ethereum Sepolia testnet. Automatic payment confirmation is handled by the `listener` service, which watches Transfer events on the blockchain (polling every 15 seconds, tuned to the limits of a free RPC provider) and updates an order's status once a transaction reaches the shop's wallet address.

## Technical stack

The back end is written in Go using the chi router, GORM with a PostgreSQL driver and a go-redis client as an alternative database, JWT authentication through golang-jwt, the Zap logger, a Prometheus client, and OpenTelemetry (otelgorm, otelsql, otlptrace) for tracing, with Testcontainers used for integration tests. The front end is built with Angular 21 using standalone components and Angular Material, with ethers.js for Web3 and MetaMask integration, tested with Vitest. The blockchain integration targets the Ethereum Sepolia testnet using an ERC20 token called MockUSDT (see the `shophub-contracts` repository) and tracks transactions through JSON-RPC `eth_getLogs` calls. Continuous integration runs on GitHub Actions with Conventional Commits enforced by commitlint, Go build and test, and a Docker image build. In deployment, a shop instance is installed through the `shop` Helm chart, used internally by `shop-operator`, and its database is provisioned through the CNPG operator for PostgreSQL or a Redis operator, depending on the choice made in the ShopHub configuration.
